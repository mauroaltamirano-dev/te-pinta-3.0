# Admin navigation (A-03)

Objective: reorganize the admin navigation into 9 entries in 6 groups, remove the Analytics stub, keep a single "Nuevo pedido" flow, unify order status labels and use one money formatter. Branch `feat/admin-navigation` from `34cdc2f`, worktree `tepinta3.0-worktrees/admin-navigation`.
Delivery: `ask-on-risk`, local work-unit commits only (no push/PR/merge/deploy), gentle-ai review per commit. Runner: `vendor/bin/phpunit` via scratchpad `run-an.sh` against `pgsql-dev` database `testing_admin_navigation`; frontend unit tests with `node --test tests/frontend/`; Playwright for navigation e2e.

## Specs

- S1 — Grouped IA: "Admin IA: 9 entries / 6 groups" (ROADMAP A-03); TARGET_ARCHITECTURE: "Admin navigation: 9 entries in 6 groups (Operación, Resumen, Catálogo, Stock y costos, Finanzas, Configuración)". Entries per `raw/ui-public-seo.md` §5: Operación = Vender (`/admin`), Pedidos, Clientes; Resumen = Panel; Catálogo = Productos, Marketing; Stock y costos = Inventario; Finanzas = Gestión; Configuración = Configuración. Desktop: "icon + visible label (~232px, collapsible to a rail that keeps tooltips), group headings, and one icon per destination". Mobile bottom bar: "Vender · Pedidos · Panel · Más".
- S2 — Visibility by permission (L3 decision): each entry is shown only when the user holds its permission; `Role::permissions()` stays the single source of truth. "Respetá los permisos RBAC existentes: cada rol sigue viendo solo lo que puede usar, y ninguna ruta pierde su `can:`."
- S3 — Absorbed destinations reachable through section navigation (§5): Inventario = "Insumos · Recetas · Producción · Ajustes de stock · Costos (Políticas inside Costos)"; Gestión = "Panorama · Movimientos · Billeteras · Compras · Auditoría ("Registrar operación" becomes a header action, not a tab)"; Marketing = "Instagram becomes a tab inside"; Configuración = "General · Marca (tenant accent/logo) · Plano del salón (editor) · Usuarios/roles (future)".
- S4 — Floor plan (L4 decision): while POS-3 is not in main, the floor plan is the "Plano del salón" section of Configuración, shown for `floor.manage`; its route keeps `can:orders.manage`.
- S5 — Labels (UX-3): "Rename to "Vender" (POS), "Ajustes de stock", and "Panel". Make the breadcrumb root "Panel"." Products eyebrow moves from "Configuración" to Catálogo (UX-11).
- S6 — "remove Analytics stub" (UX-4): "Remove it from nav until metrics are defined."
- S7 — Single "Nuevo pedido" (L5 decision): "Nuevo pedido" always leads to the POS (`/admin`) from Panel and Pedidos; `/admin/orders/create` keeps its route and `can:orders.manage`, is titled "Modo avanzado" and is linked as a secondary action in Pedidos.
- S8 — "unify status labels" (UX-6): "One `orderStatusLabels` source, imported by Dashboard. Delete `dashboardStatusLabels`."
- S9 — "one money formatter" (UX-13): "Put money/date formatting in `resources/js/lib/format.ts`." Output stays identical (`es-AR`, `ARS`, no decimals).
- S10 — Constraints: "Los nombres de la UI van en español; si un nombre o agrupación no está definido en la auditoría, preguntame antes de inventarlo." "No cambies precios, pedidos ni datos: es solo navegación, etiquetas y formato." "El tema claro ya está en main: mantené los tokens y el contraste."
- S11 — Dev environment: ".env propio en el worktree con APP_PORT=8000, VITE_PORT=5173 y APP_URL=http://localhost:8000 […], COMPOSE_PROJECT_NAME y base de dev propios, con mi catálogo copiado de tepinta_dev, para que yo pruebe con make dev."

Assumptions:
- A1 — Public pages (`pages/public/menu.tsx`, `product-detail.tsx`) keep their local formatter: `feat/public-restaurant-redesign` rewrites both files, so S-01 adopts `formatMoney` when it rebases. Admin and shared features use the single formatter.
- A2 — "Marca" lives inside the General settings page today; no new route is created, so the Configuración section nav lists General · Plano del salón · Usuarios.
- A3 — Existing on-screen labels are reused where the audit names no section ("Producto destacado" tab for `/admin/marketing`, "Costo actual" and "Políticas de costo" inside Costos).
