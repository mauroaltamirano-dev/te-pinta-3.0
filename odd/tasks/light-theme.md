# Light theme with restaurant accent (Phase 3, A-02)

Objective: replace the dark admin theme with a modern light theme whose accent color is chosen per restaurant.
Branch: `feat/light-theme-integration` (new main baseline `b61998f95a63454d01672f3072bbcb187b5c208f`; original `feat/light-theme` preserved). Delivery: `auto-chain`; chain: `feature-branch-chain` (local commits only; no PR or remote mutation). Test runner: PHPUnit on PostgreSQL (`testing_light_theme_integrated`, browser `testing_light_theme_integrated_e2e`); eslint, prettier, tsc, vite build.
Audit reference: `~/tepinta-handoffs/global-architecture-audit-2026-10/raw/ui-public-seo.md` (UX-0, token proposal, contrast table).

## Specs

- S1 — Owner's decision, verbatim: "dejemos el tema oscuro de lado, usemos un tema más moderno y actual, que será tema light obviamente, fondo claro, con los colores resaltables que será un color elegible por el cliente, en nuestor caso será el color #b84f3f para que haga las acentuaciones". The admin renders light only: no forced `.dark`, no dark-only colors.
- S2 — One set of semantic tokens as CSS variables on `:root` (e.g. background, surface, surface-muted, border, text, text-muted, accent, accent-hover, accent-text, on-accent, success, warning, danger, info) exposed to Tailwind v4; admin components use these tokens, not hex/rgb literals, `text-white`/`bg-black` or raw palette classes for themeable colors. The coral `#EA7C69` and its RGB copies disappear from the admin (including the logo SVG and the sales chart).
- S3 — Restaurant accent: `restaurants.accent_color` (hex, default `#b84f3f`). The server derives the accent scale and a text-safe shade and injects them as CSS variables in the root view, so changing the color needs no rebuild. An accent that cannot reach 4.5:1 contrast for its text shade on white is rejected by validation. Measured: `#b84f3f` on white 4.97:1 (passes); small accent text uses a darker shade (≈6.4:1).
- S4 — The accent is editable in Configuración → General ("Color de acento") with live preview, validated in the backend, by whoever can edit settings today.
- S5 — Order status and other badges are legible on white: tinted background + dark text, ≥ 4.5:1. The same status uses the same label everywhere (audit: `waiting` is "Confirmado" in Orders and "En espera" in Dashboard — unify).
- S6 — The public site keeps its layout and uses the same accent tokens where it shows the brand color.
- S7 — Barlow stays as the admin font.
- S8 — Tests: unit tests for accent scale derivation and the contrast rule; a feature test proving the root view injects the restaurant's accent variables; a feature test for the settings validation. eslint, prettier, tsc and `npm run build` pass.
