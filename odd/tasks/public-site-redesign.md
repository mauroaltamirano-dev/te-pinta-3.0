# Public site redesign

Objective: a more professional public site (home, menu, product detail, cart) within the stored palette, without new routes, endpoints or external assets. Branch `feat/public-site-redesign`, chained on `feat/category-subcategories` at `1bb7e0c` (rebased from `2292cb3`), same worktree and test runtime (`odd/tasks/category-subcategories.md` header). Delivery: local feature-branch chain, no push, merge or deploy. Test policy (stored decision `public/restaurant-redesign-2026-10/testing`): strict TDD only for changed behavior; visual units get desktop/mobile e2e and before/after screenshots, no brittle class or position tests.

## Specs

- S1 — "darle un toque más profesional a la web pública, lo dejo a tu criterio, no me convence mucho la actual". Start from the stored palette: ink `#1b1b1b`, canvas (brand accent, default `#b84f3f`), earth `#f1f1f1`; "red is accent/nav/buttons/artwork, not large backgrounds except navigation. Black/light dominate surfaces."
- S2 — "El gateway público es default-deny (deploy/cloudflare): no agregues rutas, endpoints ni assets externos fuera de lo permitido; si hace falta, documentalo y pedímelo." Allowed today: `/`, `/menu`, `/cart`, `/menu/catalog`, `/menu/{slug}`, the three checkout endpoints, `/build/assets/*.{css,js,woff,woff2}`, four brand PNGs, two icons and product images.
- S3 — "Cuidá rendimiento y SEO."
- S4 — Real catalog, prices, cart, checkout and WhatsApp hand-off keep working exactly as before (backend untouched).
- S5 — e2e desktop and mobile; before/after screenshots in the scratchpad.

## Log

- L1 (2026-10-23) — User request, verbatim: "Feature 2, web pública. Pedido del usuario: "darle un toque más profesional a la web pública, lo dejo a tu criterio, no me convence mucho la actual". - L2 — Diagnosis from `<scratchpad>/screens/before/`: `.public-theme` sets the page background to the red canvas, so the menu cards, the menu hero, the product detail and the cart are large red surfaces, against the stored palette decision; products without photo show a giant initial letter; each menu card carries three buttons and a link at the same weight, and prices are small; headings use the generic `font-serif` stack, which renders as a different system serif on each device (DejaVu Serif on Linux, Noto Serif on Android, Georgia on macOS/Windows). Engram holds the palette decision; no typography decision was stored beyond Instrument Sans for text (Vite `bunny()` fonts) and serif editorial headings in `DESIGN_SYSTEM.md`.
- L3 — Decisions. (1) Keep serif editorial headings, but bundle one real serif (Fraunces 600, latin) through the existing `laravel-vite-plugin/fonts` `bunny()` mechanism: it is downloaded at build time and served from `/build/assets/*.woff2`, already allowed by the gateway, so no gateway change and no runtime third-party request. (2) Earth/white surfaces and ink text everywhere; red only for the navigation bar, primary actions, active filters and small accents; dark ink for photographic heroes. (3) Products without photo use the allowed monogram (`/icons/te-pinta-logo.svg`) on a neutral surface. No new route, endpoint or image file.
- L4 — Implementation notes. Menu: "Unidad" stays a visible text button (an icon-only "+" next to "+ Docena" was ambiguous, and the checkout spec locates the card by it); "+ Docena" is the full-width primary action because the dozen is the main price; card media keeps the existing 16:10 contract; secondary actions sit on earth and fill with earth-ink on hover, as the existing checkout spec already defined. Header: inactive links were `white/85` on red, which blends to about 3.9:1; they are now solid white (active link underlined), and the home spec measures contrast against the header instead of the page shell. Product SEO tags were already server-rendered by `app.blade.php`; JSON-LD was not added because it needs backend changes (S4) and is not required. Performance: one bundled serif weight (latin woff2, `font-display: swap`), explicit `width`/`height` on product images, `fetchpriority="high"` on the detail photo, lazy menu images; no new requests, routes or images (S2).
- L5 — Spec updates are intended visual changes only: color expectations moved to the new palette (white cards with ink text, ink menu hero, earth page shell, earth-ink eyebrows), the card name heading is H3 under the category H2, and every WCAG ≥ 4.5 check was kept. `category-subcategories.spec.ts` now scopes "Clásicas · Dulces" to the card (the new live region repeats it).
