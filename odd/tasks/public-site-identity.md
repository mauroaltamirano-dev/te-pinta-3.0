# Public site identity

## Objective

Give Te Pinta's existing public ordering flow an original, responsive rotisería identity. The initial palette was `#333333` / `#e3e3e3` / `#b85c3f`; the user explicitly replaced it for PUI-8 with public ink `#1b1b1b`, red canvas `#b84f3f`, and light earth `#f1f1f1`. Red must now lead the composition, while the new white full wordmark remains unchanged.

The public catalog must remain a projection of administrable Product and Marketing data, not a parallel frontend catalog. Admin edits to a Product's public copy, ingredients, tags, image, slug, order, and featured schedule must flow to the public surfaces without code changes.

## Problem and why

The public home, menu, and cart are functional but visually generic, and there is no public product-detail page. Customers need a recognizable restaurant landing, fast repeat ordering, and an optional detail page for informed choices without changing backend-owned prices, validation, order creation, or WhatsApp handoff.

## Authorized scope

Visual and UX work in the existing public React/Inertia flow, a required `/menu/{slug}` product-detail route with public-only product metadata and minimal administration where missing, focused tests, and design-system documentation. No broad admin/POS redesign, invented frontend business rules, third-party assets, or remote operations.

The later source-of-truth correction authorizes PUI-6: complete only the missing Product/Admin taxonomy and slug controls, make starter catalog seeding safe for an already administered catalog, embed the existing Marketing featured scheduler inside Products administration, and prove Admin-to-Public propagation. Do not add a duplicate ProductPublicProfile for fields already on Product, a second featured flag, hardcoded public product/price/tag lists, Recipe-derived public ingredients, or a new promotion engine.

The user then supplied original brand PNGs and a landing screenshot for composition inspiration. PUI-7 integrates those local originals into the public Home and shell, replaces the visually awkward decorative line only after identifying it in the rendered page, and makes the restaurant/rotisería character more expressive without copying the screenshot or inventing products, promotions, prices, or business promises.

The latest request authorizes PUI-8: adapt every public surface to the new red-led palette, preserve the supplied white full wordmark (`logo-completo-blanco.png`) and user-edited hero headline, repair semantic token contrast, and update public palette/asset tests and design documentation. No Admin palette changes or backend commercial changes.

## Constraints

- Treat both supplied Figma Community links as composition/interaction inspiration only; exact files could not be opened from this environment, so no unverified measurements or asset claims.
- Preserve the existing server-quoted checkout, persisted order before WhatsApp redirect, and slug-based cart.
- Product detail is optional for purchasing: quick-add from `/menu` must remain. Public ingredients and tags must not expose internal Recipe/Inventory structures.
- Preserve unrelated dirty worktree edits; stage only this feature's files or hunks.
- Design system tokens remain centralized in `resources/css/app.css`; public styling must not change the admin-shell palette.
- ProductCatalogSeeder is bootstrap data, not a public runtime source. Re-running it after an Admin rename must not recreate a starter variety. Preserve test-only seeding and do not silently mutate administered prices or tags.
- Featured placement is owned by scheduled Marketing records with eligibility and overlap rules. Products administration must reuse that authority; the user explicitly approved embedding its scheduler rather than a mere link.
- Real Product images replace own temporary placeholders automatically. Do not hotlink random third-party images. Promotions/discounts are out of scope because the current Marketing module has no commercial promotion engine.
- TDD mode: unresolved (no explicit project/session setting found); no RED/GREEN claim. Runner: `npm run test:e2e -- tests/e2e/public-checkout.spec.ts`; also `npm run types:check`, `npm run lint:check`, `npm run format:check`, `npm run build` and affected PHP tests as applicable.
